01 / 能力拆解

它该被当作“音频作品生成器”来测。

公开信息显示，它支持文本及参考音频等多模态输入，目标是端到端生成包含多角色对白、背景音乐和环境音效的完整音频作品。单句 TTS 不是主战场。

核心能力

Prompt 统筹多轨

把对白、场景、情绪、音效、配乐、转场写进同一条指令，验证模型是否能自动安排时间线和声场层次。

创作价值

角色声音保持

重点观察长段生成中角色是否串音、音色是否漂移、情绪变化是否仍保留同一个人的身份感。

输入形态

文本 + 参考音频

参考音频是验证零样本复刻与长段音色一致性的关键材料，干净单人声样本直接影响复刻稳定性。

当前限制

API 开放节奏仍需确认

当前个人用户可在体验中心进行创作测试；API 侧据内部员工口径预计 2026 年 7 月中开放，最终以火山方舟官方公告和控制台入口为准。

02 / 体验路径

体验路径先确认可用入口和额度，再测成片质量。

为了避免把它测成普通配音工具，体验按“入口与额度确认 → 样本准备 → 分场景生成 → 打分复盘”推进。

Step 01

入口与额度

优先查看体验中心是否可用；API 测试需等待火山方舟控制台正式出现豆包音频生成 1.0 调用入口。

Step 02

准备素材

准备 3 类 Prompt 与 1 段 10-20 秒干净参考人声；先不用复杂后期，避免干扰模型质量判断。

Step 03

生成样片

分别生成广播剧、广告音频、参考音色一致性样片。每类至少跑 2 次，观察稳定性而非只看最好一次。

Step 04

复盘评分

按角色区分度、指令遵循、混音平衡、情绪控制、可上线程度打分，再决定是否进入生产工作流。

03 / 体验方法

评测方法围绕“输入方式、输出效果、边界记录”展开。

体验不是只听哪条更好听，而是把每次生成拆成可复盘的评测单元：输入条件、生成目标、实际效果和失败原因都要记录。

先按输入方式分层，不把所有样片混在一起比较

纯文本生成和参考音生成回答的是不同问题：前者看模型能否从 Prompt 直接调度多轨声音，后者看音色和风格能否迁移。

评测记录字段： 输入方式：纯文本 / 参考音 目标能力：全要素直出 / 音色迁移 / 高表现力 / 边界测试 目标时长：生成前标注 实际时长：生成后记录 样片编号：P / H / R / XQ / D / 错误日志
纯文本样片重点看角色、环境、音效、配乐是否能一次性编排。
参考音样片重点看音色一致、风格迁移和长段是否漂移。
高表现力样片单独看节奏、方言、戏腔、叫卖、纯音效等特殊表达。
错误日志不丢弃，作为可用性边界的一部分。

先听主样片，再按问题展开其他样片

体验路径不追求把所有音频一次铺开，而是先用主样片判断能力上限，再根据具体问题展开补充样片和参考音对照。

试听顺序： 1. 先听每组主样片，判断这一类能力是否成立 2. 纯文本样片重点听角色、音效、配乐是否共同服务叙事 3. 参考音样片先听参考音，再听成品音频，比较音色、语速和风格迁移 4. 补充样片只在需要验证某个细分问题时展开，不把播放器全部堆在页面上
主样片直接展示，承担报告的第一层证据。
其他样片用列表筛选，避免页面变成素材堆叠。
参考音生成必须同时呈现参考音和成品音频，才方便判断迁移效果。
切换播放时自动暂停上一条音频，保证试听判断不被干扰。

每条样片用“效果、能力、边界”三段评价

报告不直接写“好/不好”，而是说明听到了什么效果、它证明了什么能力、还暴露了什么边界。

评价模板： 效果：这条音频实际听起来怎样 能力：它证明了模型哪项能力 边界：这条样片仍然需要注意什么 适用场景：它能进入哪类真实工作流 错误记录：如触发风控、额度、超时、参考音长度限制，单独记录
成功样片用于证明能力上限。
失败日志用于说明产品边界和使用成本。
Demo 从完整测试集中抽取，不等同于全量测试。
评价语言面向最终报告，不保留过程草稿口吻。
04 / 测试集设计

测试集按“全量覆盖 + 实测校准”设计。

完整测试集先围绕官方能力主张拆成纯文本生成、参考音生成、长段音色一致性、高表现力表达和边界稳定性，再根据实际生成结果校准内容密度、参考音限制和风控边界。后面的样片评测只是从完整测试集中抽取代表案例，不等同于测试集全量。

全要素成片：从一条 Prompt 直出完整音频片段

覆盖科幻短剧、悬疑广播剧、古装客栈、动作逃生、纪录片等场景，用来验证“音频导演”式生成是否成立。

覆盖编号：P01-P06 输入方式：纯文本生成 核心变量：人声对白、环境声、拟音、配乐、转场 代表抽样：P02 悬疑广播剧、P01 科幻短剧、P06 古装客栈
设计依据：一条样片必须同时验证角色、环境、拟音、配乐和转场，才能证明不是普通 TTS。
实测校准：P02 最能体现音效作为剧情线索，P01 声场复杂度最高。
评估重点：对白清晰度、音效是否服务剧情、音乐是否自动避让人声。
主要边界：复杂声效越多，越容易遮挡对白或让声场变成噪音墙。

参考音生成：从“像不像”扩展到“能不能迁移”

参考音测试不能只听音色相似，还要看参考音能否迁移到播客、有声书、对话、方言适配等语境。

覆盖编号：R01-R10 输入方式：文本 Prompt + 15-25 秒干净单人参考音 核心变量：音色一致、风格迁移、长段稳定、多角色区分 代表抽样：R03 参考音播客、R08 长段参考音、R10 多参考/多角色
设计依据：参考音生成要同时测试音色、语速、气息、口音和内容风格。
实测校准：参考音模块对文本密度很敏感，内容不足会出现静寂段补时长。
评估重点：参考音是否漂移，情绪变化时是否换人，媒介声是否可区分。
主要边界：参考音整体效果弱于纯文本样片，环境音与对白更容易不融合；方言口音参考有时只迁移音色，不体现口音。
多参考融合三次实验均暴露明显问题：声音混乱、空白段变多、生成未要求内容，当前基本不建议作为可用能力展示。

高表现力：用专项测试压测“会不会演”

高表现力测试覆盖搞笑、早市叫卖、情绪争吵、脱口秀、快板、体育解说、耳语惊悚、新闻连线、冥想和无对白叙事。

覆盖编号：H01-H13 输入方式：纯文本生成 核心变量：节奏、气口、情绪曲线、生活场景、纯音效事件链 代表抽样：H02 早市叫卖、H05 快板相声、H10 无对白纯音效
设计依据：高表现力样片比普通对白更能暴露节奏、气口、场景调度和情绪控制能力。
实测校准：早市叫卖、快板和纯音效叙事最有区分度。
评估重点：是否像真实表演，是否靠停顿和反应成立，而不是朗读文本。
主要边界：方言能力需要单独测试，不能用未生成方言效果的样片替代。

方言专项：融合压力与单方言稳定性分开评估

多方言融合用于看口音切换，单方言用于看地道度和稳定性，两者回答的问题不同。

覆盖编号：D 系列 输入方式：纯文本生成 核心变量：四川、东北、粤语、天津、河南等地域表达 测试策略：融合压力测试 + 单方言专项测试
设计依据：地道方言、可懂度和不刻板化必须同时评估。
实测校准：复杂方言、多角色、长文本叠加时解析稳定性下降。
评估重点：口音是否自然、是否能听懂、是否被环境声遮挡。
主要边界：单方言更适合做可复现评估，多方言融合更适合做压力测试。

戏曲唱腔：单独展示模型的强风格上限

戏腔不是两句唱词能展示的能力，必须包含引子、念白、慢板、转快、情绪拔高和收腔。

覆盖编号：XQ01-XQ02 输入方式：纯文本生成 核心变量：板眼、拖腔、转音、唱念转换、收腔 展示结论：XQ02 更完整、更惊艳，适合作为正式展示样片；XQ01 作为短唱腔对照。
设计依据：戏曲唱腔需要足够时长展示板眼、拖腔和情绪层次。
实测校准：XQ02 的表现更完整，更适合单独展示。
评估重点：是否有戏曲韵味，是否滑向普通国风歌曲。
主要边界：纯戏腔、强风格女声、唱念类文本更容易触发风控或流式中断。

平台可粘贴格式：只把生成指令交给模型

测试集不是越复杂越好，关键是让平台能读懂哪些内容要朗读、哪些只是动作或评测说明。格式规范可以显著减少误读、少读和把说明念出来的问题。

推荐写法： 对白引号：所有实际要说出来的台词都使用中文引号，例如：店员说：“欢迎光临。” 角色标注：角色名放在引号外，用“某某说 / 某某问 / 某某低声说”表达。 动作提示：停顿、叹息、笑声、背景音放在引号外，例如：她停顿一秒后说：“我想起来了。” 时间提示：可以写“第 30 秒左右出现敲门声”，但不要让角色读出时间码。 安全粘贴：只粘贴“测试 Prompt”列，不粘贴通过标准、失败信号、测试点标记和评分说明。
避免写成“店员：欢迎光临”，平台更容易把角色名和对白边界混在一起。
避免把动作写进引号，例如“停顿一秒 我想起来了”，否则可能被当作台词朗读。
避免把测试编号、评分规则、通过标准一起粘贴进输入框，防止模型生成无关内容。
脚本必须提前预估目标时长；内容不足以撑满时长时，模型容易用大段沉默、环境声或重复停顿补时长。
05 / 样片评测

用代表样例回答：它能把声音做到什么程度。

这一组样片从完整测试集中抽取，按能力证据组织：先展示成片直出，再展示参考音迁移、高表现力表达和边界样例。每条音频都对应一个明确问题，而不是单纯陈列播放器。

选择逻辑

样例选择遵循“能力证明”而非“听感偏好”。

最终入选样例覆盖官方主张里的三类核心能力：全要素直出、参考音生成与长段音色一致性，以及非语言表达和复杂声场控制。

成片直出样例必须同时包含对白、环境、拟音、配乐或转场，能体现“一条 Prompt 生成完整音频作品”。
可听差异非技术听众也应能听出角色分离、声场层次、叫卖节奏、参考音迁移或纯音效叙事。
生产价值样例对应真实工作流：广播剧、短剧、播客、有声书、本地生活内容、短视频音效设计。
边界呈现报告保留风控、参考音时长、额度和复杂 Prompt 解析失败，避免只呈现成功样例。

纯文本生成样片

只输入文字 Prompt，不上传参考音。重点评估模型能否直接生成角色对白、环境声、配乐、叫卖节奏和纯音效叙事；方言能力另设专项测试。

主样片悬疑广播剧音效叙事

悬疑广播剧：声音线索推动剧情

钟摆停顿、录音机质感和三下敲击承担叙事功能，不只是背景装饰。这条最能代表“音频导演”能力：模型需要同时处理角色、场景、线索和转场。

科幻短剧：警报、AI 与舱门反转

低频、警报、金属门、AI 声和真人对白同时出现，适合检验模型能否在高密度声场中维持信息层级。

查看输入 Prompt 
请生成 100 秒左右的科幻短剧预告音频。需要低频紧张配乐、飞船环境声、金属门开启声、警报声、人声对白和结尾转场。音乐不能盖过对白。

古装客栈：雨夜、客栈和群像调度

雨声、木门、酒杯和古风配乐共同建立场景，能够观察模型是否具备跨题材的环境塑造能力。

查看输入 Prompt 
请生成 95 秒古风客栈群戏音频。使用普通原创角色声音。需要雨夜环境、古风低密度配乐、木门声、酒杯声、脚步声、楼上传来的动静和多人对白。配乐要有电影感，但不能盖住台词。整体是悬疑氛围，不要过度惊悚，不要夸张武侠腔。

audio_duration_lifetime累计创作额度会直接限制测试覆盖面，长音频压力测试需要提前规划顺序。
reference duration > 30s参考音频存在硬性时长上限，实际准备素材时应控制在 15-25 秒干净单人声。
script density可以设定目标时长，但脚本内容不足时会出现大段沉默、环境声或重复停顿，影响最终音频整理。
multi reference多参考融合三次实验均不稳定，出现声音混乱、大段空白和生成未要求内容，当前基本不可用。
emotion variants同一句多情绪能保持音色并形成一定区分，但情感表达不够自然契合，且出现少读一遍的问题。
sensitive voiceprint强风格人声、戏腔或疑似名人声线可能触发声纹风控，即使是纯文本生成也可能被拦截。
TextPromptAgentResultError多方言、多角色、复杂格式同时出现时，前置 Prompt 解析稳定性会下降。

指令遵循是否完整执行角色、时间、音效、情绪要求 1=大部分遗漏；3=主要要求完成；5=细节完整且稳定。 效果：角色、音效、配乐和转场大多能按 Prompt 出现。S01 短剧片头基本接近成品；P02、P01、P06、XQ02 的核心要求也能成立。个别细节音效可能缺失，但不影响主效果判断。 较强适合展示全要素直出能力。
角色 / 音色一致角色或参考音色是否前后一致 1=明显漂移；3=基本一致；5=长段仍稳定。 效果：纯文本多角色区分更稳定。参考音能迁移部分音色和语速，但整体效果弱于纯文本；方言口音参考有时只迁移音色，没有稳定体现口音。 较强纯文本可信度更高，参考音需谨慎。
对白自然对白轮次、插话、停顿、情绪是否像真实对话 1=机械朗读；3=可接受；5=有表演和互动感。 效果：纯文本广播剧和群戏更像真实对话。停顿、插话、情绪转折和角色反应较自然；参考音对话会受参考音表达风格影响，互动感下降。同一句多情绪有区分度，但情感不够贴合。 良好可用于剧情类 Demo，情绪专项还需复测。
声场与混音人声、音乐、环境声是否层次清楚 1=互相遮挡；3=基本清楚；5=声场层次好。 效果：纯文本样片声场层次更完整。雨夜、飞船、旧书房、婚礼现场等场景能建立空间感，人声、音乐、环境声基本清楚；参考音样片更容易出现环境音和对白不融合。 较强成片直出优势明显，参考音混音需验证。
非语言表达笑、叹息、呼吸、沉默是否自然服务叙事 1=突兀；3=能听出；5=自然有效。 效果：轻笑、吸气、叹息、沉默能服务叙事。P02 的敲击、R03 的轻笑和吸气、S01 的短暂停顿都能增强故事感；参考音和多情绪任务的自然度仍不稳定。 良好可作为加分项，但不宜过度堆指令。
可用性是否接近可直接用于广告、播客、广播剧或视频配音 1=不可用；3=需明显后期；5=接近成片。 效果：部分纯文本样片已经接近可直接展示的成片效果。短剧片头、悬疑广播剧和戏曲唱腔的叙事完整度较高，后期压力较小；参考音样片仍需筛选，多参考融合当前不具备可用性。 部分接近成片适合 Demo 和创意验证，正式生产需挑选稳定样片。
稳定性同一 Prompt 重跑 2-3 次质量是否稳定 1=抽奖；3=有波动；5=稳定可复现。 效果：少量样本看，效果会有波动，但差异不是很大。成功样片的整体方向较稳定；复杂 Prompt、方言融合、戏腔、参考音和多参考任务更容易出现错误、空白、少读或风控，失败日志仍需保留。 基本稳定常规样片可复现感尚可，边界任务需单独记录。
